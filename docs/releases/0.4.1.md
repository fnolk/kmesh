# kmesh 0.4.1

This release adds safer access-group changes and staged connection diagnostics.
It also includes the platform-role separation and agent enrollment changes made
since v0.3.1.

## Changes

- Separate the fixed `member` and `admin` platform roles from access groups.
  Platform administration does not automatically grant SSH access.
- Add `admin users add-groups` and `remove-groups`. Group changes show a preview
  and the target access gained or lost. Use `--dry-run` to inspect a change.
- Apply group changes and audit records in one transaction. Reject stale previews.
  Confirm removal of all existing groups, or use `--yes` in scripts.
- Add `status`, `access explain <user-id> <target-id>`, and `doctor <target-id>`.
  Diagnostics distinguish login, authorization, agent, network, and SSH service
  failures. Reports support JSON and do not print credentials.
- Make enrolled agent state self-contained. Enrollment prints the command needed
  to start the agent with its saved server and local SSH settings.
- Keep new CLI help, prompts, and results in English, with wording reviewed against
  the project's ASD-STE100 rules.

## Upgrade requirements

- From 0.3.x or earlier, upgrade the server, clients, and agents together.
  The 0.4 API is incompatible with 0.3 clients.
- Back up the old server state. Initialize a separate, empty data directory.
  Schema version 6 does not migrate earlier databases. Recreate users, access
  groups, grants, and credentials, and enroll target agents again.
- Existing 0.4.0 databases remain compatible. Upgrade the server before using the
  new group-change and access-explanation operations.
- `users groups` still replaces all memberships. Scripts that clear all existing
  groups must now pass `--yes`.
- `agent run` reads its server settings from enrolled state. Use the data directory
  printed at enrollment; do not pass server overrides or a configuration file.
- Existing active SSH connections can continue after group permissions change.
  A successful `doctor` check verifies an SSH identification, not an SSH host key
  or account authentication. Its temporary connection can appear in service logs.
