# kmesh 0.4.2

This release authenticates client commands from configured credentials and makes
access-group details easier to scan. It keeps the 0.4 API and schema version 6.

## Changes

- Authenticate commands directly with the configured token or public key.
  Token mode uses `KMESH_TOKEN` or `[auth].token`. Public-key mode obtains and
  refreshes a session using the configured username and SSH key.
- Scope public-key sessions by server, profile, username, and key fingerprint.
  Keep refresh-token rotation under a cross-process lock.
- Remove the `login` and `logout` commands and saved API-token state. Configure
  credentials before running commands.
- Focus `groups show` on group members and target grants, while retaining state,
  availability, and warnings for unavailable targets.

## Upgrade requirements

- Existing 0.4.0 and 0.4.1 databases remain compatible. This release keeps
  schema version 6 and the 0.4 API.
- Configure token authentication with `KMESH_TOKEN` or `[auth].token`, and set
  `[auth].method = "token"`. Configure public-key authentication with
  `[auth].method = "public-key"`, `username`, and `key`.
- Replace scripts that call `kmesh login` or `kmesh logout` with configured
  credentials. Configure credentials explicitly when upgrading from saved login
  state.
- Existing SSH agent enrollments and server data remain compatible.
